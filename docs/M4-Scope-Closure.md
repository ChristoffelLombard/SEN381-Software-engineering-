# M4 Scope Completion and M1 Closure

## Final status

M4 requires the team to account for every significant M1 commitment and explain variance. The final repository does not support an 80% completion claim for the full M1 scope.

### Quantified view

Using the 20 M1 functional requirements as the primary scope set and the M4 values **Met = 1, Partially = 0.5, Not Met = 0**, the evidence-based FR score is:

- Met: 3
- Partially implemented: 9
- Not met: 8
- Completion: **40%**

This is below the M4 target of 80%.

The result is not hidden by reclassifying incomplete committed capabilities as out-of-scope. The M1 baseline explicitly committed requester, staff and oversight capabilities, so incomplete items remain visible in the final closure.

## Why the percentage is lower than the M3 release presentation

The M3 recording focused on a smaller release-candidate capability set and reported five release requirements as passed. It did not provide evidence that every M1 requirement had become implemented. M4 therefore separates the M3 release-candidate evidence from the full M1 scope baseline.

## Scope conclusion

The project has a working academic demonstration baseline, but it has not completed the full M1 committed product scope to the required 80% threshold. The correct engineering conclusion is **conditional finalisation / no production go-live**, not an invented 80% score.
